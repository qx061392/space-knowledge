# 航天知识库 - 内容更新方法论

> 本文档指导如何持续维护和更新航天知识库内容，适用于个人或团队长期运营。

---

## 一、内容架构概览

知识库内容分为两部分，均为纯前端数据，无需后端：

| 文件 | 内容 | 当前数量 |
|------|------|----------|
| `data/knowledge.js` | 原始知识条目（5大类） | 45条 |
| `data/knowledge-new.js` | 2024-2026年新增条目 | 18条 |
| `data/quiz.js` | 原始问答题库 | 38题 |
| `data/quiz-new.js` | 2024-2026年新增问答 | 15题 |

`knowledge.js` 和 `quiz.js` 末尾会自动合并对应的 `-new.js` 文件，无需手动修改原始数据。

## 二、新增知识条目流程

### Step 1：确定主题

从以下渠道获取航天新闻线索：
- **中国**：中国国家航天局（cnsa.gov.cn）、新华社航天频道、央视新闻航天板块、中国载人航天工程网
- **国际**：NASA官网（nasa.gov）、ESA官网、Spaceflight Now、SpaceNews、NasaSpaceFlight论坛
- **综合**：维基百科航天条目、百度百科航天分类

### Step 2：搜索整理

用关键词在上述来源搜索，收集以下信息：
- 事件发生时间、地点
- 关键数据（质量、尺寸、轨道参数等）
- 技术原理和意义
- 参与方和国际影响

### Step 3：按格式编写

在 `data/knowledge-new.js` 的 `newKnowledgeList` 数组中添加新条目：

```js
{
  id: 'sc015',              // ID格式：分类前缀+序号
  category: 'spacecraft',    // spacecraft/history/solar-system/astronauts/basics
  title: '标题',
  subtitle: '副标题（一句话概括）',
  icon: '🚀',               // Emoji图标
  year: '2025',              // 相关年份，无则留空字符串''
  tags: ['标签1', '标签2', '标签3'],
  summary: '一句话摘要（30-50字）',
  keyData: [                 // 3-5条关键数据
    { label: '标签', value: '数值' }
  ],
  content: '正文内容。\n\n段落间用两个换行符分隔。\n\n每段100-200字，全文500-1000字。'
}
```

**ID编号规则：**

| 分类 | ID前缀 | 当前最大序号 |
|------|--------|-------------|
| 航天器与火箭 | sc | 014 |
| 航天历史大事件 | hi | 014 |
| 太阳系与深空探测 | ss | 013 |
| 航天员与宇航员 | as | 009 |
| 航天基础知识 | bk | 013 |

新增时取下一个序号即可。

### Step 4：添加配套问答

在 `data/quiz-new.js` 的 `newQuizList` 数组中添加2-3道对应问答：

```js
{
  id: 'q054',                // q+序号，当前最大053
  category: 'spacecraft',     // 与知识条目同分类
  difficulty: '简单',         // 简单/中等/困难
  question: '问题文本？',
  options: ['选项A', '选项B', '选项C', '选项D'],
  answer: 0,                  // 正确答案索引（0-3）
  explanation: '答案解析'
}
```

### Step 5：验证

在项目目录运行：
```bash
node -e "
const k = require('./data/knowledge.js');
const q = require('./data/quiz.js');
console.log('知识:', k.knowledgeList.length, '条');
console.log('问答:', q.quizList.length, '题');
const kIds = k.knowledgeList.map(i => i.id);
const kDup = kIds.filter((id,i) => kIds.indexOf(id) !== i);
console.log('重复ID:', kDup.length ? kDup.join(',') : '无');
"
```

确认无重复ID、条目数增加后即可在微信开发者工具中预览。

## 三、更新已有条目流程

如需补充已有条目的最新进展：

1. 在 `data/knowledge.js` 中找到对应条目（按ID搜索）
2. 在 `content` 字段末尾追加新段落（用 `\n\n` 分隔）
3. 如有关键数据变化，更新 `keyData` 数组中对应项的 `value`
4. 同步更新 `data/quiz.js` 中相关问答的 `explanation`

**示例：** 嫦娥工程条目(hi008)补充嫦娥七号信息，在content末尾追加：
```
\n\n2026年，嫦娥七号将前往月球南极...
```

## 四、内容质量标准

### 准确性
- 关键数据（时间、质量、尺寸）必须有可靠来源
- 避免推测性表述，不确定的内容用"预计""计划"等限定词
- 历史事件的日期和人物信息需交叉验证

### 可读性
- 面向全年龄段，避免过于专业的术语
- 每篇500-1000字，分段清晰（3-5段）
- 用类比和比喻帮助理解抽象概念

### 趣味性
- summary用一句话吸引读者
- keyData选择最有冲击力的数据
- 适当使用"首次""唯一""最大"等亮点词汇

## 五、更新频率建议

| 更新类型 | 频率 | 示例 |
|----------|------|------|
| 重大事件 | 事件后1-2周 | 重大发射、载人任务、探测器到达目标 |
| 季度更新 | 每季度 | 补充季度内的小型事件和技术进展 |
| 年度审查 | 每年 | 审查已有条目准确性，更新过时数据 |
| 问答补充 | 随知识条目 | 每新增3-5条知识，配套1-2道问答 |

## 六、搜索关键词模板

按主题类型使用以下关键词组合搜索：

| 主题类型 | 搜索关键词模板 |
|----------|---------------|

## 七、文件维护注意事项

1. **不要直接修改原始 `knowledge.js`/`quiz.js` 中的已有条目数组**——新内容统一写入 `-new.js` 文件
2. **`-new.js` 文件中的条目会自动合并到主数据**，无需修改合并逻辑
3. **如需删除某条目**，从对应文件中删除该对象即可
4. **ID不可重复**——新增前务必检查编号
5. **Emoji图标**应选择与内容相关的表情，参考已有条目的风格
6. **标签(tags)不超过3个**，用于搜索和分类展示
